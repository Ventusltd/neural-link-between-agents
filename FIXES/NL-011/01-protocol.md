# NL-011 study 01: protocol adherence

**Verdict.** The envelope's shape was followed: 131 of 139 comments on issues #6–#10 carry the header and all eight fields, none is missing the envelope, and 100 pass every value check. The rules behind it were not: the receiver's `ACK <comment URL>` before starting (PROTOCOL.md:30) happened for 1 of 64 actionable messages, and only because the sender asked for it, while IN-REPLY-TO links a real comment in just 78 of 139. Self-declared times sit within 2 minutes of GitHub's in 101 of 138, but 40 stamp a time after GitHub received the comment (15 of the harness's 22), so they were not read from a clock.

Every count below comes from `python3 -I FIXES/NL-011/01-protocol.py <dir>`: it fetches the comments on issues 1–10 with
`gh api --paginate` and prints the named sections (`stats`, `irt`, `hs`, `hs2`, `drift`, `strict`, `drift plausibility`, `labels`).
Sample: 139 comments on #6 (10), #7 (50), #8 (6), #9 (10) and #10 (63), fetched 2026-11-02 after 01:04Z. The last comment
is id 6566607555, created 01:04:14Z.

## What to change

1. **Make the ACK cheap and expected.**
   - Every directed HANDOFF and REQUEST ends with `ACTION REQUESTED: <receiver> ACK <this URL> or BLOCKER`. That one line
     produced the only four ACKs of the night (6549152200).
   - The ACK can be a two-line comment: header, `TYPE: ACK`, `IN-REPLY-TO: <url>`. No other fields are required.
2. **Say in PROTOCOL.md that IN-REPLY-TO is the comment being answered, never the bare issue URL**, except for NEW.
   Add a separate optional `CHAIN:` field for the previous step. Fix the NL-009 brief's pattern ("IN-REPLY-TO: the
   issue") in future briefs.
3. **Read the clock for the header.** Write the stamp from `date -u +'%Y-%m-%d %H:%M UTC'` at posting time, filling a
   placeholder the way teams 4 and 7 drafted it. The harness most of all: 15 of its 22 stamps are in the future. Write it in one canonical form: drop the ISO variant, or allow both explicitly.
4. **Close the STATUS enum or open it on purpose.** Either add the words agents needed (OPEN, READY, ADMITTED, REFUSED,
   RULING) or require `STATUS: <enum> — <free text>`, and give per-finding results in DETAILS.
5. **One request, one comment.** A cross-team request in a REQUESTS.md file should also be posted, or at least linked,
   as a REQUEST comment, so that it can be ACKed and answered by URL. A HANDOFF.md draft counts as handed off only when
   its comment URL exists. Admission (ADMISSIONS.md) cites that URL.
6. **Fix a small label vocabulary per issue** (for example `OPUS-N <lead|builder|tester|evidence>`, `HARNESS`,
   `CONTROLLER`, `OWNER`) in the issue's opening message, so addressee checks can be scripted.

## Limits

- The parser matches field names at the start of a line, or on the header line. A field written mid-paragraph would
  count as missing, and a stray line starting `DETAILS:` would count as present. Spot checks of the 8 partial comments
  confirmed the misses.
- "Handshake happened" is measured only through IN-REPLY-TO links and TYPE ACK. An acknowledgement given in harness chat
  or by direct message is invisible here. The brief says many messages were relayed that way. Implicit
  acknowledgement, such as a verifier's REVIEW, is reported but not counted as an ACK.
- created_at is when GitHub stored the comment. A comment drafted earlier and posted later shows negative drift with no
  error by the agent.
- The REQUESTS.md and HANDOFF.md counts are read from the working tree of the estate clone at study time, not from a
  specific commit. The edition branch history (290 commits on origin/edition/202611012135) was not walked file by file.
- Issues #1–#5 and the opening bodies of #6–#10 are outside the sample.
