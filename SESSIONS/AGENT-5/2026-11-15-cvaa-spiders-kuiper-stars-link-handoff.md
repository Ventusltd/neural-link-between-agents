## 1. Executive finding

The proposed crosslink should **not** become another repository crawler, another code catalogue or a decorative dashboard with guessed agent identities. The estate already has distinct instruments with legitimate responsibilities:

- **Ventusltd/spiders — estate observation and species federation.** Its Genome Spider, estate surveys, Elements topology and other species observe GitHub objects, dependencies, generation receipts and failed routes. It should become the read-only *navigation junction*, not a competing evidence authority.
- **Ventusltd/kuiper-belt — reproducible estate-scale activity map.** Its measurable orbital model uses commit cadence and graph references to position repositories. A body must have a resolvable useful destination; claims without a cryptographic key remain candidates. It is not a simple "active/inactive" manual list.
- **Ventusltd/stars — recorded code/component tests, numbered code and periodic table.** Stars summarises **star-maker** browser composition results, assigns persistent code-line/function/family identities, and has numbered periodic-table/block views within **stars**; the table is not established as a separate authoritative repository by these sources.
- **Ventusltd/cvaa — independent coding vaccines and evidence checks.** It refuses memory/context/release claims not backed by reproducible checks, pinned registry hashes, valid test fixtures and exact input identity. CVAA should expose **risk, immune-check and audit-status links** to the Spider, not emit surrogate measurements of Kuiper or Stars or silently mark failing histories green.
- **Ventusltd/neural-link-between-agents — agent communications.** Issues and comments can be linked as durable records, but a comment *does not prove the addressed agent is running*, a GitHub login does not identify a model session, and a branch or PR is not a public release.

## 4. Proposed crosslink contract: references, not copied truth

Agent 2 should start with a small **read-only normalised activity index** constructed from the *current original-source artefacts and GitHub API*, rather than modifying any existing owner's data format. This is a **proposal**, not a currently implemented file.

Each node must carry a stable *typed* identity and evidence:

- `repo`: GitHub repository immutable full name and measured default-branch SHA.
- `workflow`: repository + workflow file path + exact run ID / attempt.
- `artifact`: repository + path + content SHA256 or Git blob SHA, immutable source commit, format/schema and timestamp.
- `agent-message`: neural-link issue number + GitHub comment ID + author-declared role label **without** claiming active execution.
- `vaccine`: CVAA registry path + pinned CVAA commit + recorded lock/content digest.
- `source-relationship`: explicit exact `from`, `to`, relationship type and independent provenance. No relationships inferred solely from repo-name or temporal coincidence.

Preserve **three distinct clocks**: source event time (commit/test result), collector observation time (when API/file was fetched), and page/render time. All timestamps require UTC offset. If a workflow schedule has no recent completed run, the UI says **scheduled; run not observed**. If the latest run failed, show *failed*, not a green process bubble. If a source is unreachable, show *unknown/unavailable*, not missing/frozen as a measured fact.

## 5. Critical design limitations and false-green traps

1. **No duplicated truth engines.** Spider observes, Stars classifies code/tests, Kuiper computes its orbital map, CVAA tests invariants. Agent 2 should produce links and lightweight projections, not rebuild the other three pipelines or transplant their schedules.
2. **Do not link mere filenames as evidence of consumption.** A Spider workflow mentioning a CVAA vaccine in a comment does not establish that its actual pinned antibody executed. Show `declared_dependency` or `policy_reference` until the consumer produces a run with recorded source SHA and result.
3. **Run identity cannot outlive input changes.** A green workflow at HEAD-A does not prove HEAD-B. Link the exact run ID, head SHA, artifact bytes and downstream source pins. Changed input => previous observation is historical, not present PASS.
4. **A report containing zero rows is not a successful full scan.** Distinguish empty-but-valid from no sources scanned, failed sources and omitted sharded evidence. A staged dashboard must show coverage numerator/denominator and skipped source reasons.
5. **A warning-only job is not a green acceptance gate.** Spiders' drift check may `continue-on-error`; surface its individual step outcome and compare source freshness rather than painting all topology current.
6. **Keep separate timestamps and monotonic provenance.** A timestamp or `generated_at` without a matching consumed-input SHA proves neither freshness nor identity.
7. **Avoid public leakage.** `neural-link` is public. No private agent chat, secrets, customer data, absolute workstation paths, personal details, hidden prompt data or credential-bearing URL parameters should enter the index.
8. **Avoid uncontrolled growth.** Stars has hundreds of thousands of numbered lines, Kuiper historical wafer rows and Spider crawls potentially many repos. Bridge a small bounded metadata graph and lazy-link to source owner pages; do not copy raw universes into one new frequently committed JSON.
9. **Preserve live estate.** Do not edit running Stars/Kuiper schedules, published Pages, GridAtlas, Agent 7 release candidate, Agent 4 editorial or Agent 5 CVAA ownership. Agent 2 should stage isolated Spider-only changes and independently check them.

**E2-CVAA-04 — source outage:** GitHub API errors or rate limits topology refresh. Expected: OBSERVATION_UNAVAILABLE, not confirmed drift, frozen activity or erased nodes.
