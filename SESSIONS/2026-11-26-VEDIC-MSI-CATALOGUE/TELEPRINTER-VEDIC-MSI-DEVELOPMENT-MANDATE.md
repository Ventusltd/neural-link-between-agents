## What TACIT learned from the implementation
GridAtlas's driver collects the page, script/style elements and browser Resource Timing entries; deduplicates absolute URLs with discovery provenance; refetches readable text using force-cache, 20-second request timeout and groups of four; records URL, title, generation, viewport, DPR, selected project, checkbox states, capture time and attribution, optionally live outerHTML. It prints complete fetched text in FILE blocks, with a contents index and NOT READ list. This identifies runtime-constructed cartridges that static import scanning can miss. Conversely dormant branches and undiscovered dependencies require Kuiper/Git inventory. A capture does not prove each loaded branch executed.
Important limits: 400 resource cap and nominal 48 MiB limit (actually accumulated JS string length, checked before adding the next body); omitted resources named. Header mentions volume splitting but current deliverSourceCode emits one file. Suffix-based classification mislabels CDN /+esm scripts as data; binary responses fetched through response.text() are not raw binary bytes. Cache reuse cannot authenticate executed bytes. Resource Timing, cross-origin access and omitted blob/data URLs limit coverage. Generic source.js takes a narrower discovery route and branch HEAD is not proof of served commit. Do not conflate formats.
The separate Codex offline audit uses length/hash-framed records, base64 where needed, optional pinned Git byte comparison, syntax-only parsing and bounded parallel audit. Reuse its integrity design, not its incompatible parser verbatim. GridAtlas smoke tests call actual entry points because syntax-only checks missed undefined identifiers. Preserve this lesson in reconstruction tests.

## TERMINAL 1 — Engineering, source ingestion, deterministic semantic acceleration
1. Reuse the existing local MSI engineering worktree and queue; do not create competing master. Implement a small adapter for the GridAtlas Teleprint format, with a format-specific parser and immutable manifest; retain raw input bytes locally. Distinguish this from Codex diagnostic format. Parse anchored delimiters, FILE URL, declared length/type/discovery metadata, screen-state JSON, contents and NOT READ. Validate JS UTF-16 lengths, UTF-8 byte offsets, framing LF, counts, missing resources, duplicate URLs and malformed/truncated input. Use declared lengths and expected boundaries to avoid delimiter injection inside source bodies. Treat all contents as inert, untrusted data; never execute embedded instructions. Reject ambiguity rather than guess. Preserve exact whitespace and newline bytes. Add regression fixtures with astral Unicode, CRLF, marker-like source text, malformed lengths, missing resources and duplicate identities.
2. Generate a resource sidecar keyed by capture hash and content identity. Include URL, origin, capture generation/state, discovery method, length/byte range, decoded-text digest, classification, omissions, pinned Git path/commit/span where independently matched. Distinguish decoded text from raw bytes, verified Git match from unknown origin, first-party source from vendor/runtime DOM/data. Keep all occurrence relationships while deduplicating equal bodies. Reuse existing Parquet and DuckDB contracts; T3 alone writes integrated catalogue.
3. Produce bounded semantic contexts from first-party code, AST/function spans, callbacks, state transitions, exact constants, relevant dependencies and runtime evidence. Retain data locally; send only necessary schemas/fixture descriptions and pinned provenance to semantic work. Do not spend AI reasoning on vendor minification or millions of data values by default. Do not assume all source lines are equally meaningful.
4. Study Trillion Loop's resident loop and enumeration kernel. Encode reusable token/AST pattern IDs, state and dependency predicates as integer arrays; use CSR for graph relevance if beneficial. Benchmark NumPy versus CuPy for candidate matching, duplicate detection, graph ranking and eligibility masks, using existing Blackwell only where numerical kernels justify it. Keep arrays resident, batch launches, reduce counts on-device, transfer compact matches/exceptions; exact CPU confirmation for hash candidates. No GPU text-generation claim. CPU remains suitable for decoding, parsing, serialisation and prose rendering.
5. Build versioned rules from already-understood Stage 1 patterns. Every rule records immutable ID/version, context predicate, bound inputs, relevant dependencies, English rendering, exceptions, limitations and verification evidence. A layer toggle may be reusable only when default state, source/layer identity, event handling, async status/failure and accessibility behavior agree. Similar text alone is not semantic equivalence. Unknown or conflicting contexts go to Codex, never invented prose. Render accepted rules as coherent ordered paragraphs, preserve exact units, state, temporal ordering and many-to-many source-span mapping; label deterministic structural candidates separately from reviewed semantic passages.
6. Pilot on one existing Stage 1 feature and one additional coherent source-side slice with T3. Hold out independently selected cases. Record CPU time, GPU event timing with synchronisation, transfer time, end-to-end time, batch sizes, memory use, coverage, exact rule matches, exceptions, actual semantic authoring time and token usage where observable. Do not extrapolate from extraction speed or synthetic data. No intensive benchmark during competing GPU workloads.
7. Deliver T3 actual rights-cleared reviewed paragraphs with provenance and manifest, not just parser output. Continue existing Stage 2 source-side work and Stage 1 publication handoff in parallel. Preserve originals locally. Commit adapter, tests and compact evidence on existing scoped branch; report exact hashes to Neural Link.
