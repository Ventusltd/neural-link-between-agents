# VEDIC — Continuous English digital twin: revised acceptance contract
26 November 2026 — TACIT b t b a
Owner clarification supersedes any earlier keyword-first or dictionary-first presentation. Read alongside Turn18 and MSI overnight supplement. VEDIC is a continuous, natural, conversational English representation of the actual software, accessible to people with zero programming knowledge. The ambition is for a person using a PC and AI assistance to understand, experiment with, and independently recreate equivalent behavior. This is not a claim that prose alone has already achieved reconstructability.

## Translation requirements
Translate coherent source spans in operational order into connected paragraphs. Explain what happens, when, why where evidenced, what information is received, how it is transformed, where it goes, how state changes, how the user interacts and what happens under every material condition. Preserve exact constants, units, algorithms, comparisons, data structures, ordering, defaults, error and boundary behavior, dependencies, UI labels, layout/style constraints and side effects. Do not silently repair existing defects, infer unstated intent, omit detail or fabricate examples as actual behavior. Describe uncertainty and missing evidence. Plain English sentences, not isolated verbs, lists of keywords, pseudocode masquerading as prose or generic summaries. Keep identifiers where they are needed for exactness and explain them naturally. A single source line can have several contextual roles; preserve every occurrence and contextual link. For each paragraph store source repo/commit/blob/path/line spans, dependency links, prose order, model/prompt/version and evidence status. Preserve comments, declarations, configuration, nonexecuting content and exclusions honestly. Do not represent whitespace as computational behavior. A line-level row links to the relevant passage and, where necessary, its own role; rows are storage, not the reading experience. Do not label an entire function verified because one sentence or sample passed.
## Agent amendments
A1: extract ordered functions/modules and source spans, data/control flow and cross-module links; preserve line coverage and context, not random keyword extraction.
B1: generate source-grounded, natural connected English paragraphs in manageable contextual batches; use AST facts and local model; include exact computational details, unresolved ambiguities and no invented behavior. Maintain consistent terminology and paragraph transitions across batches; use stable references for dependencies and a reading-order manifest. Store generated candidates separately from verified prose. WordNet and existing VEDIC words are only auxiliary search/index aids, never primary translation.
C1: independently audit prose for omissions, invented behavior, incorrect precision or ordering, and traceability. Test a small clean-room reconstruction: independent implementer receives only prose and explicitly declared external dependencies/datasets, not original code, tests that expose implementation or generated code snippets. Compare resulting behavior with original using separately held fixtures and regression checks; report gaps, not equivalence unless evidenced. Distinguish semantic accuracy, source coverage and reconstruction success.
D1: primary reading view is a continuous book-like narrative grouped by application, component and operational sequence; REPD-style paginated search/index leads to the relevant passage, with expandable source/evidence and optional function usage cards. Maintain plain-English usability for a non-programmer, source details optional. No forced keyword or table-only reading.
E1: attach safe existing runnable demonstrations, input controls and usage instructions to passages, only within existing admission/rights boundaries. Allow people to experiment and observe outputs; distinguish the original execution from any reconstructed prototype. No unapproved execution or admission.
F1: extend logical schema with ordered prose_passages (passage_id, application, section, ordinal, text, context hash, evidence status), passage_source_links (passage_id, occurrence_id, source span, role) and passage_dependency_links. Preserve canonical IDs and existing contracts via additive versioned schema/manifest. Measure actual contextual coverage, omissions, translation throughput and reconstruction outcomes separately; single writer, local checkpoints. Supervisor integrates contract and master only after exact peer handoffs.
