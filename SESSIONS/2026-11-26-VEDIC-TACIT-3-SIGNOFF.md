## 1. Purpose

VEDIC is the plain-English functional dictionary of GlobalGrid2050, not another computational engine. Its purpose is to enable people, Python programs and future agents to discover what existing code does before loading implementation details. A meaningful entry identifies a capability, its inputs, outputs, units, limits, exact source and the application where a person can encounter it. This makes a large federated estate navigable without repeatedly reading every repository. It also makes reuse, questioning and independent verification easier. The dictionary remains an ordinary two-dimensional, searchable, sortable register in the established REPD/SCADA style. Its public value comes from useful meanings and functioning application links, not from visual complexity or impressive inventory totals.

## 2. The three identities

Git identifies exact historical implementation bytes through repository, commit, path, blob and source span. Modular Star independently numbers unique physical lines, tablets, elements and functional families. VEDIC allocates permanent meaning IDs and creation timestamps; the same word can have different senses, and a meaning can acquire additional evidence without losing its original identity. None of these identifiers can substitute for the others. A source line number is not a permanent Stars line ID. A matching function name does not prove a family match. Kuiper projects existing keys into a navigable mathematical space, not a new identity allocator. Its deterministic placement is not semantic proof or evidence that every key is collision-free. Unknown joins stay null. Tacit 1 alone allocates dictionary identities; preserve earlier allocations, timestamps and historical source associations.

## 4. Catalogue and evidence

A source-reviewed meaning is different from an executable proof. The owner's later instruction supersedes artificial public demonstrations: link the actual application, describe precise activation controls and declare when that particular function's runtime is unverified. Internal synthetic fixtures remain useful for CI. The Code column immediately after Application provides pinned Git spans, raw module links and component sources for compositions. Existing Stars and Kuiper retrieval should supply exact code and dependencies when joins are proven. Repo-level links are not exact permanent addresses. Never promise that arbitrary copy-and-paste code works independently. Distinguish static review, fixture execution, hosted CI, real browser execution and served-byte verification.
