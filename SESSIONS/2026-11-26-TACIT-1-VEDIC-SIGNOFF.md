## 1. Mission and architecture

VEDIC is the plain-English functional dictionary of GlobalGrid2050. Its purpose is intent-first discovery: a researcher should describe what they want to achieve, discover an existing capability, understand its limitations, open the working application, retrieve its original source and identify compatible reusable components. Executable code is the implementation payload, not the primary human interface. The dictionary should serve non-programmers and programmers equally, helping prevent the estate from repeatedly solving the same problem.

Git preserves history; Modular Star preserves structure; VEDIC preserves meaning. Kuiper supplies an existing address-space and navigation system. Spider, Maths Genome, Periodic Table, Chemistry and CVAA supply relationships, mathematical classification, compatibility and verification. The existing Spider Printer and Teleprinter support inspection and faithful capture. Wafer, Cosmic and Furnace are existing systems, not products to reconstruct inside VEDIC. Maintain a simple two-dimensional REPD-style register, with searchable meanings, filters, sorting and expandable details. Do not build another cosmic renderer or programming runtime.

## 2. Identity, reuse and evidence

Every meaning has a permanent GG2050-VEDIC number, original UTC creation timestamp and distinct semantic key. Its implementation links to immutable Git repository, commit, path, blob and exact source span. Its structural identity comes from the producer's existing Modular Star tablet, element, family and numbered lines. These identities are related, not interchangeable. A word can express multiple meanings; aliases need not create extra meanings. One function can support several capabilities, and several implementations can satisfy one contract.

Preserve earlier allocations and their evidence. Priority, description and classification can evolve without renumbering. Allocate a new identity only for a genuinely distinct meaning or composition. Use typed inputs, outputs, units, dependencies, side effects, assumptions and limitations to distinguish meanings. Compositions reference existing IDs and compatible ports; reject cycles and unsupported compatibility claims. An open-ended composition space does not establish that every combination works.

The Code column follows Application. It links to precise Git source lines, raw modules, the existing Modular Star code report and Kuiper repository navigation. ORIENT links both component functions. Modular Star already offers copying, dependency links and reusable imports. Exact family and Kuiper line-key joins remain unresolved; do not infer identity from matching names. Copyable source is not necessarily executable alone. Record dependencies, licence, required data, surrounding state and tested conditions before asserting reproducibility.
